# Project rules

## Release notes

- Every **minor** or **major** release must have an English release note at `docs/releases/vX.Y.Z.md`.
- Paste that content into the matching GitHub release body.
- Patch releases may skip a separate note, but a user-facing hotfix still needs a short note.
- A release note should cover: what changed, behavior/security implications, upgrade notes, install, compatibility, and verification.
- Keep `CHANGELOG.md` and the release note consistent.
- Do not publish a minor/major release without the release note in the repository.
