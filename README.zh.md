# dsh-mail-plugin

[English](README.md) | 中文

**DeepSeek Harness（DSH）邮件插件**：通过 IMAP 读取邮箱、监听新邮件，并在 Agent 会话中发送经过审核的 multipart HTML 回复。

这是一个社区插件，不是 DeepSeek 官方项目。

- **侧边栏面板**：左侧 **邮件** 入口，包含“审核”和“设置”两个标签页。
- **Agent 工具**：列出/读取邮件、起草 HTML 回复、发送已批准的草稿。
- **审核机制**：未受信任收件人的回复必须由你批准后才会发送。
- **受信任收件人**：支持精确地址（`test@example.com`）和域名（`example.com`，含子域名）。
- **后台监听**：轮询新邮件并唤醒最近使用过邮件工具的会话；受信任收件人可自动发送。
- **无运行时依赖**：基于 Node 内置模块实现的轻量 IMAP/SMTP/MIME。

适用于支持 LOGIN 或 SASL PLAIN、并通过 TLS/STARTTLS 提供 IMAP4rev1 和 SMTP 提交的标准邮箱。未实现各服务商专用的 OAuth 流程；需要时请使用应用专用密码。

## 环境要求

- DeepSeek Harness `>=0.2.2-rc.2 <0.3.0`，并使用 Web UI（侧边栏面板和审核接口依赖 Web carrier）。
- 一个支持 IMAP 和 SMTP 提交的邮箱账户。
- Gmail 需要应用专用密码；要求 OAuth 的 Microsoft 账户不受支持。

## 安装

### 从 npm 安装

在 DSH 中打开 **插件 → 添加插件**，输入：

```text
dsh-mail-plugin@1.1.0
```

也可以让 Agent 使用 `plugin_manager`，`action: "install_bundle"`，`target` 填写上面的包名。安装对当前 profile 生效，重启后保留。

### 从 GitHub 安装

如果要跟踪某个提交：

```text
git+https://github.com/rzakbrodalko/dsh-mail-plugin.git#<完整40位提交>
```

请使用完整 commit，而不是分支或标签，便于 DSH 后续更新。

### 本地开发

通过 **插件 → 添加插件** 安装本地目录，或让 `plugin_manager` 的 `target` 指向该目录的绝对路径。修改 Host 代码后需要重启或重新启用插件。

## 配置

1. 点击左侧 **邮件**。
2. 打开 **设置**，填写：
   - 邮箱地址和可选显示名称
   - IMAP 主机、端口和安全方式（993/TLS、143/STARTTLS 或 None）
   - SMTP 主机、端口和安全方式（465/TLS、587/STARTTLS 或 None）
   - 用户名（与邮箱地址不同时）
   - 邮箱密码
   - 收件箱和已发送文件夹名称
3. 点击 **测试连接**，确认 IMAP 和 SMTP 均可用。
4. 点击 **保存设置**。
5. 设置 **审核策略**：
   - **除受信任收件人外均需审核**（默认）
   - **始终审核**
   - **从不审核**：所有草稿自动批准，请谨慎使用
6. 可选：启用 **自动回复** 并选择轮询间隔。

密码保存在 DSH 凭据存储的 `mail-plugin/default` 记录中。设置、草稿和监听状态保存在 `$DSH_HOME/mail-plugin/`（通常是 `~/.dsh/mail-plugin/`）。

## 使用

直接用自然语言让 Agent 操作，例如：

```text
读取我最近的五封邮件并总结。
```

```text
用 HTML 回复 Alice 的邮件，确认会议时间并询问议程。
```

Agent 会调用：

| 工具 | 作用 |
|---|---|
| `mail_list` | 列出最近邮件：UID、发件人、主题、日期、未读状态、摘要 |
| `mail_read` | 读取一封邮件，可选择标记为已读 |
| `mail_reply` | 创建 multipart/alternative HTML 回复草稿，带线程头 |
| `mail_send` | 发送已批准或自动批准的草稿 |
| `mail_drafts` | 查看草稿的审核/发送状态 |
| `mail_status` | 查看账户、审核策略、监听状态和待审核数量 |

`mail_reply` 只创建草稿；真正发送必须调用 `mail_send`。如果返回 `reviewRequired: true`，草稿会留在 **邮件 → 审核**，Agent 无权批准。

### 受信任收件人

每一行可以是：

| 条目 | 覆盖范围 |
|---|---|
| `test@example.com` | 仅该精确邮箱 |
| `example.com` | 该域名及其子域名下的所有地址 |
| `*.example.com` | 等同于域名 `example.com` |

条目会自动去除首尾空白并转为小写。相比整个域名，精确地址更安全。

### 后台监听

启用后，DSH 运行期间会按 30–300 秒（默认 60 秒）轮询收件箱：

1. 检测保存的 UID 位置之后的新未读邮件。
2. 唤醒最近使用过邮件工具的会话，并附带 UID 列表。
3. Agent 读取邮件、起草回复；只有审核策略允许时才发送。
4. 跳过来自本邮箱自身和带有 `Auto-Submitted` 头的邮件，降低回复循环风险。
5. 入队后推进 UID 位置，避免重复处理。

启用监听时会记录当前邮箱位置，因此不会处理之前的旧邮件。**立即检查** 可以手动执行一次。监听基于轮询，不是 IMAP IDLE，并且需要一个活动的 DSH 会话。

## 安全

**启用自动回复前请务必阅读本节。** 完整威胁模型和报告流程见 [SECURITY.zh.md](SECURITY.zh.md)。

### 插件能力

- 通过 IMAP 读取配置的邮箱。
- 通过 SMTP 以配置账户发送邮件。
- 在本地保存邮箱设置和草稿正文。
- 作为 DSH Host 插件在进程内运行，拥有与 DSH 相同的进程权限；它不是沙箱。

### 凭据

- 密码保存在 DSH 凭据存储，不写入插件配置、会话日志或仓库。
- 密码只会发送到配置的 IMAP/SMTP 服务器。请使用 TLS；选择 `None` 会以明文传输凭据。
- 建议使用应用专用密码；机器或 profile 泄露时请立即撤销。
- 卸载插件不会删除凭据、设置或草稿。需要时手动清理 `$DSH_HOME/mail-plugin/` 和 `mail-plugin/default` 凭据记录。

### 自动发送

- 只有受信任列表中的收件人才会跳过审核。
- 域名条目会信任该域名下的 **所有** 地址；私人账户建议使用精确地址。
- 受信任邮箱一旦被入侵，可能触发未经审核的回复；插件无法区分真实发件人和冒用者。
- 监听会跳过本邮箱地址和 `Auto-Submitted` 自动回复，但没有绝对可靠的循环保护。启用后请持续观察邮箱。

### 提示注入与模型行为

- 邮件内容是**不可信输入**。监听提示要求 Agent 将其视为数据，但模型仍可能被诱导。
- 模型可能出错、误读请求或给出错误答案。审核机制是高价值收件人的主要防线。
- 邮件插件本身不授予文件系统访问权限；文件或 shell 权限来自 DSH 会话的其余部分，仍受 DSH 沙箱和批准策略约束。
- 插件不能在发出的邮件中附加文件；回复只是 HTML 文本。

### 本地数据

- `$DSH_HOME/mail-plugin/settings.json`：地址、服务器、文件夹、信任列表。
- `$DSH_HOME/mail-plugin/drafts.json`：完整草稿正文和邮件元数据。
- `$DSH_HOME/mail-plugin/watcher.json`：最近 UID 和监听状态。
- 在支持的平台上以仅所有者可读写的权限写入。请保护 DSH home 和备份。

### 网络与隐私

插件只连接你配置的 IMAP/SMTP 服务器，不包含遥测、分析或第三方 HTTP 调用。审核预览使用 sandbox 和严格 CSP，阻止远程图片和脚本，因此审核时不会加载跟踪像素。

### 加固清单

- IMAP/SMTP 使用 TLS，除本地测试外不要选择 `None`。
- 使用应用专用密码，不要使用主账户密码。
- 优先信任精确地址，而非整个域名。
- 敏感场景保持审核开启。
- 只在能够观察邮箱时启用监听。
- 使用满足需要的最小 DSH 权限和工具集。
- 安装社区插件前检查源码。

## 限制

- 每个安装只支持一个邮箱，没有多账户选择器。
- 不支持 OAuth；仅支持应用专用密码。
- 不支持附件（读取时列出，但不会下载或发送）。
- 没有 IMAP IDLE；监听基于轮询。
- 草稿不同步到服务器草稿箱，保存在插件本地。
- 纯文本提取是启发式的，复杂 HTML 可能丢失格式。
- 已发送副本写入是尽力而为；失败会给出警告，但不会回滚已成功的发送。
- 面板目前提供英文和简体中文；其他语言回退到英文。
- 不支持自签名 TLS 证书。
- 监听在入队后会越过该 UID；如果模型随后失败，不会自动重试。未读邮件仍保留在邮箱中，可手动处理。

## 故障排查

| 现象 | 检查 |
|---|---|
| IMAP 登录失败 | 服务商是否启用 IMAP、应用专用密码、主机/端口/安全方式、用户名 |
| SMTP 登录失败 | 是否启用 SMTP 提交、465/TLS 或 587/STARTTLS、应用专用密码 |
| 证书错误 | 服务器证书必须通过系统信任链验证；不支持自签名证书 |
| 已发送副本警告 | 配置的已发送文件夹不存在或只读 |
| 监听没有反应 | 是否启用、间隔是否保存、DSH 是否运行、活动会话是否用过邮件工具、状态是否报错 |
| 未受信任发件人没有收到回复 | 草稿在“邮件 → 审核”等待批准；Agent 无权批准 |
| “没有活动的监听会话” | 先在聊天中使用一次邮件工具，再查看状态 |

## 开发

无依赖、无构建步骤。

```bash
node test/smoke.mjs
node test/protocol.mjs
```

源码结构：

- `index.js`：Host 入口，工具、审核 HTTP 路由、监听生命周期。
- `client.js`：Web 客户端，侧边栏图标、审核/设置面板、轮询。
- `lib/mime.js`：MIME 解析/构建，multipart/alternative。
- `lib/imap.js`：IMAP 客户端和监听原语。
- `lib/smtp.js`：SMTP 提交。
- `lib/socket.js`：带缓冲的行/TLS socket。
- `lib/store.js`：设置、草稿、监听状态。
- `lib/service.js`：账户访问、审核策略、工具、RPC。
