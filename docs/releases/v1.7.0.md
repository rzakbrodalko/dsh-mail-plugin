# dsh-mail-plugin 1.7.0

Sent-history reuse and configurable draft retention.

## Added

- **Clickable Recently sent** — up to 20 sent drafts appear in the Review panel. Select one for a read-only view of its subject, recipients, sent time, and attachments.
- **Make a draft again** — create a fresh review draft from a sent message. The new draft keeps the subject, HTML body, recipients, and a copy of the attachments.
- **Draft history settings** — Settings → **Draft history** controls how many sent and rejected drafts are retained:
  - Sent: default **100**
  - Rejected: default **50**
  - `0` means keep all
- Rejected drafts are also clickable for read-only inspection.

## Behavior

- **Make a draft again** creates a new draft with a new id and `pending_review` status. It never sends automatically, even if every recipient is trusted.
- The new draft clears `In-Reply-To` and `References`, so it starts a fresh message rather than silently joining the old thread.
- Attachments are copied into the new draft’s own storage; the original sent draft remains unchanged.
- Pending, approved, and failed drafts are **never** removed by retention.
- Only sent and rejected history is capped.
- Removing a draft also removes its `outgoing/<draft-id>` attachment copy.
- Retention is applied when settings are saved and whenever drafts change.

## Security

- Reused drafts always pass through user review.
- Attachment-bearing drafts continue to require review regardless of recipient trust.
- Retention deletes only local plugin history; it does not delete messages from the mail server.
- The old sent draft is never mutated or re-sent directly.

## Upgrade

Upgrading from `1.6.0` requires no migration. Existing drafts, contacts, trusted recipients, settings, and attachments are preserved. Draft retention starts with conservative defaults (100 sent, 50 rejected); existing history below those limits is untouched.

## Install

```text
dsh-mail-plugin@1.7.0
```

Use **Plugins → Add plugin** in DSH, or `plugin_manager` with `action: "install_bundle"` and that spec as `target`.

## Compatibility

- DSH `>=0.2.2-rc.2 <0.3.0`
- Web UI required
- No runtime dependencies
- Standard IMAP4rev1 + SMTP submission; no OAuth
